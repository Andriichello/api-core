# The signed-in user

`GET /api/auth/me` returns the signed-in user with what a client needs to know about the session, and
`PATCH /api/auth/me` lets the user change their own name, timezone and locale. Both work with a token or a session.

## Getting the user

```http
GET /api/auth/me
Authorization: Bearer 1|psg1ogx0XOjm3lwj62rDnyNDuZHdaW4Ha4RhmRT5c503a0e5
```

```json
{
    "data": {
        "id": 1,
        "organization_id": 1,
        "name": "Ann",
        "email": "ann@example.com",
        "timezone": "UTC",
        "locale": "en",
        "metadata": null,
        "email_verified_at": "2026-10-19T21:01:12.000000Z",
        "suspended_at": null,
        "last_login_at": "2026-10-19T21:01:12.000000Z",
        "created_at": "2026-10-19T21:01:12.000000Z",
        "updated_at": "2026-10-19T21:01:12.000000Z",
        "deleted_at": null,
        "password_updated_at": "2026-10-19T21:01:12.000000Z",
        "main_account_id": null,
        "is_password_update_required": false,
        "organization": {
            "id": 1,
            "slug": "acme",
            "name": "Acme"
        },
        "roles": ["user"],
        "permissions": ["viewAny models.users", "view models.users"],
        "impersonator": null
    },
    "message": "OK"
}
```

The route has no `password.updated` middleware, so a user who must replace their password still gets it, and the
client learns from `is_password_update_required` that it should ask for a new one.

## MeResource

`Core\Http\Resources\MeResource` is the shape of the user in `me`, in the login response and in the switch response.
It has the user's attributes (the password is hidden) and these fields:

| Field                         | Description                                                                              |
|-------------------------------|------------------------------------------------------------------------------------------|
| `main_account_id`             | The main account this account is [linked](06-linked-accounts.md) to, or `null` for a main account |
| `password_updated_at`         | When the person last set their password themselves (read from the main account), or `null` |
| `is_password_update_required` | `true` when someone else set the password; see [Required password update](10-required-password-update.md) |
| `organization`                | `{id, slug, name}` of the user's organization, or `null`                                  |
| `roles`                       | The names of the user's roles                                                             |
| `permissions`                 | The names of all of the user's permissions, given directly or through roles               |
| `impersonator`                | `{id, organization_id, name, email}` of the user who [switched](05-switching-accounts.md) to this account, or `null` |

`main_account_id` is hidden when a user is serialized anywhere else; `MeResource` adds it for the signed-in user only.
After a switch, `me` returns the account switched to, with `impersonator` set.

## Updating the user

`PATCH /api/auth/me` changes the signed-in account's own profile:

| Field      | Rules                                  |
|------------|----------------------------------------|
| `name`     | sometimes, string, max 255             |
| `timezone` | sometimes, string, a valid timezone (`timezone:all`) |
| `locale`   | sometimes, string, max 5               |

```http
PATCH /api/auth/me
Authorization: Bearer 1|psg1ogx0XOjm3lwj62rDnyNDuZHdaW4Ha4RhmRT5c503a0e5
Content-Type: application/json

{"name": "Ann Baker", "timezone": "Europe/Kyiv"}
```

The response is the updated user as a `MeResource`, with the message `Updated`:

```json
{
    "data": {
        "id": 1,
        "name": "Ann Baker",
        "timezone": "Europe/Kyiv",
        "impersonator": null
    },
    "message": "Updated"
}
```

(`data` is shortened here.) The email and the password can't be changed here; the password has its own route,
[`change-password`](07-passwords.md). `UpdateMeRequest` extends `UpdateRequest`, so a body without any of the three
fields is refused rather than answered `Updated` with nothing changed:

| Status | Field    | Message                                                                     |
|--------|----------|-----------------------------------------------------------------------------|
| `422`  | `fields` | The request has no fields to update.                                        |
| `422`  | `fields` | None of the given fields can be updated: email, password.                   |
| `422`  | `body`   | The body must be a JSON object of the fields to save, such as {"name": "…"}. |
| `422`  | a field  | The usual validation messages, e.g. for an unknown timezone                 |

The `locale` must be one of `api-core.locales` (422 `The selected locale is invalid.` otherwise), as the `locale`
middleware and the emails use only those (see [The locale middleware](../localization/00-locale-middleware.md)).
